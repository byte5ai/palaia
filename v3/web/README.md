# palaia v3 web

The dashboard shell (Vite + React + TypeScript + Tailwind v4), implementing
`v3/docs/design/system.md` and `principles.md` on top of Lume
(`v3/docs/design/lume/`) — SPEC-109. Feature screens (wizard, explorer,
review queue, …) are SPEC-110's; this package delivers the design tokens,
component library, app shell, live-state layer and the typed API client
they compose into.

```bash
npm ci
npm run dev             # Vite dev server
npm test                # vitest
npm run test:a11y       # axe-core scan of the shell
npm run lint            # eslint + the hardcoded-design-value scan
npm run typecheck       # tsc -b
npm run build           # production build -> dist/ (served by palaia-hub)
npm run storybook       # Ladle: the living style guide for every component
npm run storybook:build # static Ladle build -> build/
npm run gen:api         # regenerate src/lib/api/schema.gen.ts from the hub's OpenAPI schema
```

## Layout

- `src/styles/tokens.css` — the Lume tokens, bound directly (colors,
  type, spacing, radii, elevation, motion, and the `.lume-*` material
  recipes). Copied byte-identically from
  `../docs/design/lume/colors_and_type.css`; the only structural edits
  are palaia's own accent default (atelier) and the `prefers-color-scheme`
  mirror for `data-mode` (see the file's own header comment).
- `src/styles/fonts.css` + `src/assets/fonts/` — self-hosted Geist /
  Geist Mono / Source Serif 4 (variable WOFF2, OFL-1.1). Never the Google
  Fonts CDN that `colors_and_type.css` and the static mockups carry for
  reviewer convenience.
- `src/styles/components.css` — the component inventory from
  `system.md` §2 (buttons, cards, nav, tables, badges, empty states,
  forms, …), built only from the tokens above.
- `src/components/` — the React component library, one file per
  component family, each with a `*.stories.tsx` for Ladle.
- `src/shell/` — the app shell: `Sidebar`, `Topbar`, `AppShell`, nav
  config and icons.
- `src/lib/events.ts` — `useEventStream`, the live-state layer: a React
  hook around the hub's `/api/events` SSE stream (health snapshots +
  vault-change events; no refresh button anywhere in this system).
- `src/lib/api/` — the typed API client. `schema.gen.ts` is generated by
  `npm run gen:api` (`scripts/generate-openapi-schema.py` dumps the
  hub's OpenAPI schema, `openapi-typescript` turns it into types); both
  the schema dump (`openapi.json`) and the generated types are committed
  so a plain `npm ci && npm run build` never needs Python or a running
  hub.
- `src/lib/theme.tsx` — theme (`data-mode`) and accent (`data-accent`)
  control, defaulting to the system color-scheme preference with a
  manual override, remembered per-browser.
- `scripts/lint-tokens.mjs` — the "nothing hardcodes a colour/duration
  outside the token files" lint rule `npm run lint` runs.

## Serving

`npm run build` produces `dist/`; `palaia_hub.static.mount_dashboard`
serves it with SPA fallback (any client-side route still resolves to
`index.html`) whenever `PALAIA_WEB_DIST` (or the default `../web/dist`
relative path) points at a real build — `palaia-hub serve` is one
process, one port, for both the API and the dashboard.
