# palaia v3 web

The dashboard (Vite + React + TypeScript + Tailwind v4), implementing
`v3/docs/design/system.md` and `principles.md`: the design tokens, component
library, app shell, live-state layer, typed API client and every screen.

```bash
npm ci
npm run dev             # Vite dev server
npm test                # vitest
npm run test:a11y       # axe-core scan of the shell and every screen
npm run lint            # eslint + the design-token lint + the generated-tokens check
npm run typecheck       # tsc -b
npm run build           # production build -> dist/ (served by palaia-hub)
npm run storybook       # Ladle: the living style guide for every component
npm run storybook:build # static Ladle build -> build/
npm run gen:tokens      # regenerate src/styles/tokens.css from ../design/tokens.json
npm run gen:api         # regenerate src/lib/api/schema.gen.ts from the hub's OpenAPI schema
```

## Layout

- `src/styles/tokens.css` — **generated** from `v3/design/tokens.json` by
  `v3/design/gen-tokens.mjs` (`npm run gen:tokens`); never edit it by hand.
  Light by default, dark under `prefers-color-scheme: dark` unless
  `data-theme="light"` pins light, and always under `data-theme="dark"`. The
  docs site's `palaia-tokens.css` comes from the same file.
- `src/styles/fonts.css` + `src/assets/fonts/` — self-hosted Nunito Sans and
  Days One (WOFF2, OFL-1.1), identical to the website's. No font CDN.
- `src/styles/components.css` — every component and screen layout, built only
  from the tokens (`system.md` §2).
- `src/components/` — the React component library (PageHeader, Card, ListRow,
  StatusPill, Button, Field, Callout, Disclosure, Dialog, EmptyState, Stepper,
  …), each with a `*.stories.tsx` for Ladle.
- `src/shell/` — the app shell: `AppShell` (sidebar, icon rail, app bar and
  drawer, page header from the route's `handle`), `Sidebar`, nav config,
  `NotificationBell`, icons.
- `src/routes/` — the screens and the route table, including redirects from
  every earlier address (`REDIRECTS` in `routes/index.tsx`).
- `src/lib/events.ts` — `useEventStream`, the live-state layer around the
  hub's `/api/events` stream (health and memory changes; no refresh buttons).
- `src/lib/health.ts` — the one wording for palaia's state, shared by the
  sidebar and the Overview.
- `src/lib/api/` — the typed API client. `schema.gen.ts` is generated by
  `npm run gen:api` (`scripts/generate-openapi-schema.py` dumps the hub's
  OpenAPI schema, `openapi-typescript` turns it into types); both the schema
  dump (`openapi.json`) and the generated types are committed so a plain
  `npm ci && npm run build` never needs Python or a running hub.
- `src/lib/theme.tsx` — Appearance (System / Light / Dark) as `data-theme`
  on `<html>`, remembered per browser.
- `scripts/lint-tokens.mjs` — rejects literal colours and transition
  durations outside the token files, and any `var(--…)` that nothing defines.

## Serving

`npm run build` produces `dist/`; `palaia_hub.static.mount_dashboard`
serves it with SPA fallback (any client-side route still resolves to
`index.html`) whenever `PALAIA_WEB_DIST` (or the default `../web/dist`
relative path) points at a real build — `palaia-hub serve` is one
process, one port, for both the API and the dashboard. In the packaged image
nginx serves the build and proxies `/api`, `/mcp`, `/oauth`, `/.well-known`
and `/telegram/webhook` to the hub.
