# palaia 3.0.0-rc7 — seventh v3 release candidate

**Fixes from a guided install rehearsal and an independent pre-build review.** Everything from [`3.0.0-rc6`](https://github.com/byte5ai/palaia/releases/tag/v3.3.0.0-rc6) is here; this note lists what changed since. An AI assistant walked a fresh server through the published setup, the server was rebooted under real conditions, and a second review went through the code before this build.

> [!IMPORTANT]
> **This is a release candidate, not a final release.** Run it, break it, tell us — and keep backups.

## Try it

On a Linux server (tested on Ubuntu 24.04):

```bash
curl -fsSL https://get.palaia.ai | sh
```

The installer sets up Docker and Tailscale if they are missing and prints the address of a one-time setup page and its code. Open the page in your browser, enter the code and log in to Tailscale; the page then offers cloud access for ChatGPT and Claude. When it prints `done ✓`, open the address it shows; palaia's setup takes you to a working AI connection.

Already running Docker? The container on its own:

```bash
docker run -d --name palaia-hub \
  -p 8420:8420 \
  -v palaia_home:/data \
  --restart unless-stopped \
  --security-opt no-new-privileges:true --cap-drop ALL \
  --read-only --tmpfs /tmp --tmpfs /run \
  ghcr.io/byte5ai/palaia-hub:beta
```

Other ways to install — Docker Compose, Synology, Raspberry Pi, a VPS created with the server-creation file — are in the [install guide](https://github.com/byte5ai/palaia/blob/main/v3/deploy/README.md).

This tag publishes the container image as `ghcr.io/byte5ai/palaia-hub:beta` and `ghcr.io/byte5ai/palaia-hub:v3.3.0.0-rc7` (amd64 + arm64), and attaches the Raspberry Pi appliance image to this release.

## New since rc6

**Connecting AI apps**
- **AI apps can finish connecting.** After **Allow** the browser stayed on palaia's page instead of returning to the Claude app, claude.ai or ChatGPT; the sign-in pages' security policy blocked that step. It now allows exactly the step back to the app address palaia checked, and nothing else.

**Install and reboots**
- **palaia comes back after a reboot even when the tailnet address is late.** A small boot unit waits for the address and starts the hub; a hub stopped on purpose stays stopped.
- The installer no longer shows Tailscale's "run `tailscale up`" hint, which the setup page contradicted.

**Security**
- The curator session gets only palaia's curator tools — no built-in tools, none of your Claude Code settings, no other MCP servers (needs Claude Code 2.1.248 or later). Its guards judge the note a change really lands on, and its edits can only add tags.
- Bad tokens on the AI connection no longer stall the hub; two simultaneous first-run requests can no longer both create the owner; notes are never read or written through a symbolic link inside a memory.
- Dependency advisories in the dashboard, docs site and extension tooling resolved or documented.

**Memories and backups**
- A backup taken while palaia writes restores a working git history.
- A temporary memory that cannot be moved into the archive stays registered and working.
- A new capture about the same subject gets its own identity instead of a retired one's.
- Overview says search works while the search index is still being built, and updates by itself.

The full list is in the [changelog](https://github.com/byte5ai/palaia/blob/main/v3/CHANGELOG.md).

## Known gaps

- Connecting the ChatGPT and Claude apps themselves was not part of this candidate's automated checks: the connection was tested with a standard OAuth client in a real browser over a public HTTPS address, not with the vendors' apps.
- Tailscale's own service was not part of the checks: the test network ran a self-hosted control server (Headscale), and public HTTPS went through a Cloudflare tunnel to the same cloud entry. On Tailscale's service your tailnet may ask you once to allow Funnel; the setup page shows that link.
- The curator's own tools under the new session flags were not exercised in a live curator run.
- The Claude Desktop extension was built and signed inside the image, not installed in Claude Desktop itself; the server-creation file (`cloud-init`) was not booted on a real cloud provider.
- In Claude Code, the published setup prompt gets only a summary of the setup guide (#615); chat apps were not checked for this.
- [`v3/RELEASING.md`](https://github.com/byte5ai/palaia/blob/main/v3/RELEASING.md) lists what still stands between this RC and 3.0.0.
