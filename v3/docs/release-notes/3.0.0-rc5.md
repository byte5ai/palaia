# palaia 3.0.0-rc5 — fifth v3 release candidate

**Install in the browser, connect ChatGPT and Claude, and a new look.** Everything from [`3.0.0-rc4`](https://github.com/byte5ai/palaia/releases/tag/v3.3.0.0-rc4) is here; this note lists what changed since. It carries the fixes from the first supervised installation test of rc4.

> [!IMPORTANT]
> **This is a release candidate, not a final release.** Run it, break it, tell us — and keep backups.

## Try it

On a Linux server (tested on Ubuntu 24.04):

```bash
curl -fsSL https://get.palaia.ai | sh
```

The installer sets up Docker and Tailscale if they are missing and prints the address of a one-time setup page and its code. Open the page in your browser, enter the code and log in to Tailscale; the page then offers cloud access for ChatGPT and Claude. When it prints `done ✓`, open the address it shows; palaia's setup takes you to a working AI connection.

Already running Docker? The container on its own:

```bash
docker run -d --name palaia-hub \
  -p 8420:8420 \
  -v palaia_home:/data \
  --restart unless-stopped \
  --security-opt no-new-privileges:true --cap-drop ALL \
  --read-only --tmpfs /tmp --tmpfs /run \
  ghcr.io/byte5ai/palaia-hub:beta
```

Other ways to install — Docker Compose, Synology, Raspberry Pi, a VPS created with the server-creation file — are in the [install guide](https://github.com/byte5ai/palaia/blob/main/v3/deploy/README.md).

This tag publishes the container image as `ghcr.io/byte5ai/palaia-hub:beta` and `ghcr.io/byte5ai/palaia-hub:v3.3.0.0-rc5` (amd64 + arm64), and attaches the Raspberry Pi appliance image to this release.

## New since rc4

**Install**
- **`curl -fsSL https://get.palaia.ai | sh` works on Ubuntu again.** The installer is plain `sh`; under Ubuntu's `dash` it used to stop at its first line.
- **Join your private network in the browser.** Without a key, the installer starts a one-time setup page you open in your browser (protected by a code) where you log in to Tailscale. The page closes itself and the port with it.
- **Cloud access during install.** The same page offers to let ChatGPT and Claude reach palaia over HTTPS through Tailscale Funnel — only palaia's AI connection, never the dashboard. Keep it private if you prefer.
- **Keys stay out of command lines.** A Tailscale key goes in as a root-only file (`PALAIA_TSKEY_FILE`) that Tailscale reads itself; the installer deletes it afterwards.
- **"Done" means ready.** The installer and the container report success only when the hub's own health check answers, not when the page loads.
- Works on a server that already runs Docker or is already on your tailnet, and keeps an existing firewall as it is.
- The server-creation file runs the same installer.

**Cloud access**
- **A separate door for the internet.** Tunnels point at palaia's cloud entry, which answers only the AI connection and its sign-in; the dashboard and its API stay on your private network. The hub keeps that door shut until you turn cloud access on.
- **An honest self-test.** palaia checks its own public address the way ChatGPT and Claude do and reports each result; a wrong tunnel, an unrelated page or an open dashboard fails with the fix named. A new address that does not answer yet is checked again by itself for a few minutes.
- **Sign-in from an empty hub works.** Turning on sign-in before your first memory is refused with a reason instead of stopping the hub; signing in to the private dashboard in Cloud mode no longer loops.
- **Restart from the browser** where palaia runs in its container.

**First-run setup**
- Opens by itself until it is finished, resumes where it stands after a reload or restart, and ticks only what palaia really has.
- One forward order: how you'll use palaia, your first memory, your account, cloud access, your first AI app — no trip back to an earlier step.
- Required and optional fields are marked, with what an empty value does; the example text no longer names a company.
- The Claude app, claude.ai and ChatGPT are offered as cloud connectors next to Claude Desktop and the command-line tools.

**Look and words**
- **A new, calmer design** across the dashboard, the first-run setup, the installer's setup page, the sign-in pages, the docs site and the panels palaia shows inside Claude and ChatGPT: one set of colours and type for light and dark, larger click targets, a visible focus ring, and status always as a word, never colour alone.
- **Five places in the menu.** Overview, Memories, AI apps, Add-ons and Automations, with everything about the server under Settings. Old addresses and bookmarks still lead to the right page.
- **Plain words everywhere.** Memory instead of vault, AI app instead of client, access key instead of token, Private / Cloud / Public with what each one means. Long explanations moved behind "What's included?" and "Advanced"; every page has one obvious next step.
- **AI apps** shows each app's status ("Connected — last request 2 min ago" also after a restart), lets you revoke or replace an app's access key, and walks you through connecting one.
- **Access & sign-in** splits the old switch in two: "Require sign-in for this dashboard" and "AI apps need an access key".
- **Backups** has one Download button, says plainly what the file contains, and shows the setting that unblocks it.

**Fixes**
- **A restored backup starts again.** The databases in a backup were stored as owned by root; restored the documented way, palaia could not open them and never became ready. New backups keep the right owner, and the restore steps fix the owner for older ones.
- Opening the Telegram settings by their address works again: only `/telegram/webhook` goes to the hub, not every `/telegram` page.

**Documentation**
- The setup guide for AI assistants follows the new install and setup, including a key handoff that never touches the chat, and the save-and-find check before calling setup done.
- The install page lists the first-run steps in their real order; restoring a backup on a server set up with `get.palaia.ai` re-runs the installer instead of a hand-written `docker run`.

The full list is in the [changelog](https://github.com/byte5ai/palaia/blob/main/v3/CHANGELOG.md).

## Known gaps

- Connecting the ChatGPT and Claude apps themselves was not part of this candidate's automated checks: the sign-in and the AI connection were tested with a standard OAuth client over a public HTTPS address, not with the vendors' apps. Please tell us how it goes.
- Tailscale's own service was not part of the checks either: the test network ran a self-hosted control server (Headscale). The login on the setup page went there, and since it has no Funnel, public HTTPS went through a Cloudflare tunnel to the same cloud entry. On Tailscale's service your tailnet may ask you once to allow Funnel; the setup page shows that link.
- The server-creation file (`cloud-init`) runs the same installer, but it was not booted on a real cloud provider for this candidate.
- The setup guide for AI assistants has two lines its user runs on their own computer (a hidden password prompt and the Tailscale key handoff). They were tested in Linux shells, not on a Mac.
- Documented client results: [`v3/docs/client-matrix-results.md`](https://github.com/byte5ai/palaia/blob/main/v3/docs/client-matrix-results.md); [`v3/RELEASING.md`](https://github.com/byte5ai/palaia/blob/main/v3/RELEASING.md) lists what still stands between this RC and 3.0.0.
