# palaia 3.0.0-rc9 — ninth v3 release candidate

**Setting palaia up on a server you already have no longer saves its password.** Everything from [`3.0.0-rc8`](https://github.com/byte5ai/palaia/releases/tag/v3.3.0.0-rc8) is here; this note lists what changed since.

> [!IMPORTANT]
> **This is a release candidate, not a final release.** Run it, break it, tell us — and keep backups.

## Try it

On a Linux server (tested on Ubuntu 24.04):

```bash
curl -fsSL https://get.palaia.ai | sh
```

The installer sets up Docker and Tailscale if they are missing and prints the address of a one-time setup page and its code. Open the page in your browser, enter the code and log in to Tailscale; the page then offers cloud access for ChatGPT and Claude. When it prints `done ✓`, open the address it shows — usually `http://palaia/` — and palaia's setup takes you to a working AI connection.

Already running Docker on a Linux machine at home? The container on its own:

```bash
docker run -d --name palaia \
  --network host -e PALAIA_CLOUD_BIND=127.0.0.1 \
  -v palaia_home:/data \
  --restart unless-stopped \
  --security-opt no-new-privileges:true --cap-drop ALL \
  --read-only --tmpfs /tmp --tmpfs /run \
  ghcr.io/byte5ai/palaia:beta
```

Then open `http://palaia.local:8420/` from another device on the same network. Docker Desktop (macOS, Windows), Docker Compose, Synology, Raspberry Pi and a VPS created with the server-creation file are in the [install guide](https://github.com/byte5ai/palaia/blob/main/v3/deploy/README.md).

This tag publishes the container image as `ghcr.io/byte5ai/palaia:beta` and `ghcr.io/byte5ai/palaia:v3.3.0.0-rc9` (amd64 + arm64), and attaches the Raspberry Pi appliance image to this release.

## New since rc8

**Setup with an AI assistant**
- **An existing server's password is used once and saved nowhere.** When you log in to your server with a password, the install guide uses it only once, to let in a key made just for this install; the key is removed from the server when setup is done. The assistant first checks whether its commands really run on your computer, asks how you log in before trying any login, and never guesses a user name (#631).
- **Claude Code reads the whole setup guide.** The setup prompt now asks an assistant that can run commands to read the guide in full, instead of the summary Claude Code's web fetch gives. Chat apps without commands read it as before (#615).

**Fixed**
- **No error in the log when an AI app ends its session.** Every normal session end left "Error in standalone SSE writer" and a stack trace in the hub's log. That report came from the MCP library and meant nothing was wrong; the hub now leaves out exactly this one (#627).

**Security**
- **The library behind `palaia.local` is pinned and audited.** The image installed it in whatever version was newest at build time, outside the release check's audit. It is now in the lockfile like every other library; no known security holes (#626).
- **Two libraries updated for published advisories.** `dnspython` 2.9.2 (CVE-2026-128089, high) and `fastmcp` 3.4.11 (GHSA-7xgj-8392-5q4r, moderate). palaia was exposed to neither: it never parses DNS zone files and uses no per-tool authorization rules. The release check's audit of the image's libraries is clean.

The full list is in the [changelog](https://github.com/byte5ai/palaia/blob/main/v3/CHANGELOG.md).

## Known gaps

- The new setup prompt reaches the docs at palaia.byte5.ai/docs with the site's next update.
- Unchanged from rc8: the Raspberry Pi redirect was checked on an x86 test machine with the same units, not on Pi hardware; Synology's Container Manager with the host network was not checked.
- Unchanged from rc8: the ChatGPT and Claude apps themselves, Tailscale's own service and Funnel, Claude Desktop installing the extension, and the server-creation file on a real cloud provider were not part of the checks; the test network ran a self-hosted control server (Headscale).
- [`v3/RELEASING.md`](https://github.com/byte5ai/palaia/blob/main/v3/RELEASING.md) lists what still stands between this RC and 3.0.0.
