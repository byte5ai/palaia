# palaia 3.0.0-rc8 — eighth v3 release candidate

**palaia opens by name.** Everything from [`3.0.0-rc7`](https://github.com/byte5ai/palaia/releases/tag/v3.3.0.0-rc7) is here; this note lists what changed since. On your tailnet palaia is now `http://palaia/`, on your home network `http://palaia.local:8420/` with Docker, and `http://palaia.local/` on the Raspberry Pi image.

> [!IMPORTANT]
> **This is a release candidate, not a final release.** Run it, break it, tell us — and keep backups.

## Try it

On a Linux server (tested on Ubuntu 24.04):

```bash
curl -fsSL https://get.palaia.ai | sh
```

The installer sets up Docker and Tailscale if they are missing and prints the address of a one-time setup page and its code. Open the page in your browser, enter the code and log in to Tailscale; the page then offers cloud access for ChatGPT and Claude. When it prints `done ✓`, open the address it shows — usually `http://palaia/` — and palaia's setup takes you to a working AI connection.

Already running Docker on a Linux machine at home? The container on its own:

```bash
docker run -d --name palaia \
  --network host -e PALAIA_CLOUD_BIND=127.0.0.1 \
  -v palaia_home:/data \
  --restart unless-stopped \
  --security-opt no-new-privileges:true --cap-drop ALL \
  --read-only --tmpfs /tmp --tmpfs /run \
  ghcr.io/byte5ai/palaia:beta
```

Then open `http://palaia.local:8420/` from another device on the same network. Docker Desktop (macOS, Windows), Docker Compose, Synology, Raspberry Pi and a VPS created with the server-creation file are in the [install guide](https://github.com/byte5ai/palaia/blob/main/v3/deploy/README.md).

This tag publishes the container image as `ghcr.io/byte5ai/palaia:beta` and `ghcr.io/byte5ai/palaia:v3.3.0.0-rc8` (amd64 + arm64), and attaches the Raspberry Pi appliance image to this release.

## New since rc7

**Open it by name**
- **On your tailnet: `http://palaia/`.** The installer and the setup page give the server's tailnet name instead of a number, and palaia's first-run setup and sign-in use it from the start. Needs MagicDNS (on by default for new Tailscale networks); without it palaia gives the number and says how to turn MagicDNS on.
- **One name: `palaia`.** The server's tailnet name, the container and the command inside it are all `palaia`, and the image is now `ghcr.io/byte5ai/palaia`.
- **No port number on the tailnet.** Port 80 on the server's tailnet address leads to palaia too. If another program already uses it, palaia keeps `:8420` and says so.
- **At home with Docker on Linux: `http://palaia.local:8420/`.** The Docker command and the Compose file run on the machine's own network, so the name reaches your other devices. Docker Desktop keeps its own command with the published port.
- **Raspberry Pi image: `http://palaia.local/`**, without a port, through a redirect on the Pi itself; if another program uses port 80, palaia stays on `:8420`.

**Security**
- On the machine's own network the cloud entry stays on the loopback address.
- On the Pi, port 80 keeps each device's own address, so the limit on failed sign-ins still counts per device.

The full list is in the [changelog](https://github.com/byte5ai/palaia/blob/main/v3/CHANGELOG.md).

## Known gaps

- On the tailnet path every device reaches palaia with the same address inside the server, so the limit on failed sign-ins counts all of them together (#621). This was already so in earlier candidates.
- The Raspberry Pi redirect was checked on an x86 test machine with the same units, not on Pi hardware; Synology's Container Manager with the host network was not checked.
- Unchanged from rc7: the ChatGPT and Claude apps themselves, Tailscale's own service and Funnel, Claude Desktop installing the extension, and the server-creation file on a real cloud provider were not part of the checks; the test network ran a self-hosted control server (Headscale).
- In Claude Code, the published setup prompt gets only a summary of the setup guide (#615).
- [`v3/RELEASING.md`](https://github.com/byte5ai/palaia/blob/main/v3/RELEASING.md) lists what still stands between this RC and 3.0.0.
