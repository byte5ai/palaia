# palaia 3.0.0-rc6 — sixth v3 release candidate

**Security and setup fixes after an independent review of rc5.** Everything from [`3.0.0-rc5`](https://github.com/byte5ai/palaia/releases/tag/v3.3.0.0-rc5) is here; this note lists what changed since. It carries the fixes from a code review of rc5 by a second AI model and from a full installation run on a fresh server.

> [!IMPORTANT]
> **This is a release candidate, not a final release.** Run it, break it, tell us — and keep backups.

## Try it

On a Linux server (tested on Ubuntu 24.04):

```bash
curl -fsSL https://get.palaia.ai | sh
```

The installer sets up Docker and Tailscale if they are missing and prints the address of a one-time setup page and its code. Open the page in your browser, enter the code and log in to Tailscale; the page then offers cloud access for ChatGPT and Claude. When it prints `done ✓`, open the address it shows; palaia's setup takes you to a working AI connection.

Already running Docker? The container on its own:

```bash
docker run -d --name palaia-hub \
  -p 8420:8420 \
  -v palaia_home:/data \
  --restart unless-stopped \
  --security-opt no-new-privileges:true --cap-drop ALL \
  --read-only --tmpfs /tmp --tmpfs /run \
  ghcr.io/byte5ai/palaia-hub:beta
```

Other ways to install — Docker Compose, Synology, Raspberry Pi, a VPS created with the server-creation file — are in the [install guide](https://github.com/byte5ai/palaia/blob/main/v3/deploy/README.md).

This tag publishes the container image as `ghcr.io/byte5ai/palaia-hub:beta` and `ghcr.io/byte5ai/palaia-hub:v3.3.0.0-rc6` (amd64 + arm64), and attaches the Raspberry Pi appliance image to this release.

## New since rc5

**Security**
- **Another site can no longer change anything in palaia through your browser.** Every change to the dashboard's API has to come as JSON from the dashboard's own page, in every mode, also on a private hub without sign-in. Scripts that post to a route without a body now need `Content-Type: application/json`.
- **Sign-in stays on without a memory.** A hub with sign-in turned on but no memory yet still asks for the owner's password.
- **The cloud self-test only checks public https addresses** and counts only a refusal as "admin stays private" — a redirect, a sign-in prompt or an error now fails the check.
- Restart from the browser accepts only the dashboard's own request; the session cookie keeps `Secure` behind a TLS tunnel; failed sign-ins through a tunnel are counted per caller.

**Install**
- The installer removes a key file also when run with `sudo`, skips cloud access when another program uses its port, keeps a custom data folder on a re-run, and treats only a firewall rule for everyone as "port open".
- The server-creation file writes the Tailscale key only after the installer has downloaded.

**Dashboard and setup**
- **Opening the dashboard before signing in no longer locks you out for a minute** in Cloud or Public mode.
- **Switch to Private keeps the dashboard sign-in** and moves signing in to the dashboard's private address; choosing "private" in setup after turning cloud access on turns it off.
- **The Claude Desktop extension download works in the container image** — it used to fail every time — and on a private hub it connects to the private address. The image grows by about 167 MB for the Node runtime this needs.
- Smaller fixes: tunnel commands match the mode being set up, revoking an app's access also stops a freshly downloaded extension, Backups names memories outside the data folder, the last setup step's buttons work, and Overview counts an app that signs in as connected.

The full list is in the [changelog](https://github.com/byte5ai/palaia/blob/main/v3/CHANGELOG.md).

## Known gaps

- Connecting the ChatGPT and Claude apps themselves was not part of this candidate's automated checks: the sign-in and the AI connection were tested with a standard OAuth client over a public HTTPS address, not with the vendors' apps. Please tell us how it goes.
- The Claude Desktop extension was built, signed and checked inside the image (amd64), not installed in Claude Desktop itself; the arm64 image (Raspberry Pi) was not checked for it.
- Tailscale's own service was not part of the checks: the test network ran a self-hosted control server (Headscale), and public HTTPS went through a Cloudflare tunnel to the same cloud entry. On Tailscale's service your tailnet may ask you once to allow Funnel; the setup page shows that link.
- The server-creation file (`cloud-init`) runs the same installer, but it was not booted on a real cloud provider for this candidate.
- The setup guide for AI assistants has two lines its user runs on their own computer (a hidden password prompt and the Tailscale key handoff). They were tested in Linux shells, not on a Mac.
- Documented client results: [`v3/docs/client-matrix-results.md`](https://github.com/byte5ai/palaia/blob/main/v3/docs/client-matrix-results.md); [`v3/RELEASING.md`](https://github.com/byte5ai/palaia/blob/main/v3/RELEASING.md) lists what still stands between this RC and 3.0.0.
