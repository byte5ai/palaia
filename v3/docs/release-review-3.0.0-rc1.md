## 1. Verdict

**Not release-ready as a public `3.0.0`.** The core memory engine, the OAuth
2.1 server's cryptography, PKCE, redirect matching, token storage, the
dashboard's XSS/CSRF posture and the container hardening are solid and well
tested. The blockers sit at the seams: hub-wide MCP endpoints and the admin
REST surface mounted without authentication, client tokens forwarded to third
parties, the file watcher never wired in, and three shipped features that do
not work in production (update check, curated marketplace, docs links). All
are small to medium fixes; none require redesign except the admin-gate
topology (B5), which needs a decision.

## 8. Recommended path to 3.0.0

1. **Auth topology (B1, B3, B5, H1, H2).** Attach the profile-style verifier to every hub-wide mount; run `check_gateway_auth_policy` before mounting or roll back; keep the verifier on the semantic-routing router; gate `/api/backup` unconditionally and make the admin gate independent of `oauth_server`; add the missing `scope_error` calls; preserve profile fields on upsert. Add the 401 tests from §7.1–7.3 and 7.5.
2. **Token hygiene (B2).** Set `forward_incoming_headers = False` on upstream clients (or wrap the proxy so only configured auth is sent); add the negative test.
3. **Data path (B4, H9–H15).** Wire `VaultWatcher` in `serve.py`; route catalog access through the engine lock or a snapshot; make reindex skip paths written during the rebuild and never commit mid-rebuild; publish the event even when the commit fails (or fail the write loudly); `GIT_LITERAL_PATHSPECS=1`; refuse to re-render malformed frontmatter; fingerprint chunks before marking `ready`; move the PRAGMAs inside the rebuild `try`.
4. **Shipped-but-broken features (B7, B8, B9, B10, H19).** `annotations: index,manifest:…` in `v3-release.yml` and/or descend into the index in `update.py`; compare pre-release suffixes; real curated signing key + disk cache (or mark the marketplace preview); `DOCS_BASE_URL = https://palaia.byte5.ai/docs` with a drift test; dispatch `v3-pi-image.yml` from the cut workflow. Deploy the docs site before the tag, or the onboarding links stay dead.
5. **Onboarding truthfulness (B6, H20, H21, web mediums).** Put the token into every generated snippet and docs page (`--header "Authorization: Bearer …"` / `bearer_token_env_var`), or make OAuth the default connect path and say so; either build the owner-account step into the wizard or remove the promise from docs; drive the sidebar mode from `/api/mode`; link the wizard; fix the dead CTAs.
6. **Team/automations (H5, H16–H18, H22).** Validate CLI overrides through `HubConfig`; extend the loop guard to self-emitted events and cap/prune outboxes; make `messenger_check` at-least-once (return delivered-unacked rows or a redelivery window); fix the container-update plan.
7. **Release mechanics and docs.** Fix pre-release detection and the changelog guards; reconcile `RELEASING.md` (§3 additions, §4 contradictions); complete the rc1 changelog; fix the threat model's claims and dead links before sending the external-review brief; `publish.yml` tag filter (v2-track PR); `v3-ci.yml` paths; pin the container uid and add `user:`/chown guidance to the store packages; fill the `[DECISION]` placeholders; close #232.
8. **Owner items already listed in RELEASING.md** (external review, usability session, security reporting channel) remain; the external review should start only after step 1 and step 7's threat-model corrections, otherwise the reviewer audits a document that misdescribes the surface.

Steps 1–4 are the release gate. Steps 5–7 decide whether the "60 seconds" story in the README is true on day one.
